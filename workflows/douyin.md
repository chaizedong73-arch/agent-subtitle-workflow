# 抖音工作流

> 抖音和其他平台最大的不同：**通用下载器（yt-dlp 之类）基本拿不到**。
> 它有签名、有滑块验证、图文页对游客还有登录墙，所以这条路要换一种走法。
> 下面是验证可行的一套做法，不是唯一解；抖音改版频繁，失效了要自己探。

---

## 一、为什么不能沿用通用流水线

| 环节 | B 站 / YouTube | 抖音 |
|---|---|---|
| 直链获取 | 页面里的公开接口，稳定 | 需要签名参数，通用下载器解析不出 |
| 无头浏览器 | 基本可用 | **限流 + 弹滑块验证码** |
| 游客访问 | 大多可以 | 图文详情页对游客直接登录墙 |
| 结论 | `yt-dlp` 够用 | 必须**登录态 + 真实浏览器渲染** |

所以抖音这条路的骨架是：**用已登录的浏览器打开真实页面 → 从渲染后的 DOM 里取东西**，而不是去逆接口。

⚠️ **不要写"无头截图 + OCR"的临时脚本**。实测这条路必然失败：无头模式必弹滑块，即使注入了刚拿到的 cookie，图文详情页对游客仍然只给登录墙。失败不是脚本写错了，是这条路本身不通。

## 二、准备登录态

1. 用 Playwright 起一个**有界面**的浏览器（`headless=False`），人工扫码登录一次；
2. 把登录态存成 storage state / cookie 文件；
3. 之后每次提取复用它。**过期了再扫一次**，不要每次重扫。

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    b = p.chromium.launch(headless=False)   # 必须 False，headless 会被滑块挡
    ctx = b.new_context()
    page = ctx.new_page()
    page.goto("https://www.douyin.com/")
    input("扫码登录后回车...")
    ctx.storage_state(path="state.json")     # 复用这份
```

**两个容易忽略的点：**

- **浏览器必须显式走代理**（如果所在网络访问抖音需要代理）。另起浏览器不传代理会 `ERR_CONNECTION_CLOSED`，页面根本没加载，于是永远停在登录墙 —— 看起来像 cookie 失效，其实是网络没通。
- **cookie 等于账号凭据**，不要提交进仓库、不要贴进对话。

## 三、视频：先解决"这条到底有没有音轨"

抖音的播放流里，**往往同时存在无音轨的预览流和带音轨的正片流**。只抓第一条就下结论"这个视频没有声音"，是这条路上最常见的误判。

推荐做法：

1. **收集页面上所有候选播放流**（不要只取第一个）；
2. 对每条候选**远程探测**：是否有音轨、时长多少（`ffprobe -show_streams` 或下载头部判断）；
3. **选"有音轨且时长最长"的那条**；
4. 只有所有候选都确实没有 `Audio:` 时，才判定为无声视频。

拿到音频之后，转写部分和通用流水线完全一样：`ffmpeg` 抽 16k/mono wav → 切段 → 云端 ASR。可直接用 [`scripts/asr_pipeline.py`](../scripts/asr_pipeline.py) 的后半段（`--backend ark`），只需自己提供本地音频文件：

```bash
python scripts/asr_pipeline.py ./douyin_audio.m4a -o video.txt
```

## 四、图文帖：完全是另一条线

抖音「图文」笔记**没有音轨**，ASR 那套不适用。它要的是**图片 + 图上文字**。

识别方法：分享链接形如 `v.douyin.com/xxx/` 或 `douyin.com/note/<id>`。

处理顺序（按可靠性排）：

1. **用登录态渲染真实页面**，从 DOM 里抓图片直链（DOM 顺序即页序）；
2. ⚠️ 图片直链**经常返回 403**（有签名时效），这时退化成**对渲染后的页面截图**，再逐页 OCR；
3. OCR 用你自己的视觉模型跑，把结果按页组织成纯文本。

**结论：能拿到文字，但"配图"往往是渲染截图而不是原图直链。** 如果你要的是原图，得另想办法（例如在浏览器里手动保存），不要指望脚本能稳定拿到原始 PNG。

## 五、踩过的坑

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 一直弹登录墙 / 验证码 | 用了无头浏览器 | 换 `headless=False` + 复用已登录 state |
| 页面加载不出来、`ERR_CONNECTION_CLOSED` | 浏览器没走代理 | 给 Playwright 显式传 proxy |
| "拿不到详情/详情为空" | 登录态过期 | 重新扫码，刷新 state |
| 明明有声音却判"无音轨" | 只取了第一条预览流 | 收集全部候选后按音轨+时长挑 |
| 路径报"文件不存在" | Windows 下用了 `/c/Users/...` 这种 POSIX 路径 | 改用 `C:/Users/...`（大写盘符 + 半角冒号） |
| 短时间连续多条失败 / 429 | 并发太高 | 串行跑，条与条之间留间隔 |

## 六、别把它当稳定接口

抖音的页面结构、签名、验证策略变动频繁。**同一段代码隔几个月可能就失效**，这是正常的，不是"这个项目烂"。

对策：

- 把"取流/取图"这部分**隔离成单独一个函数**，改版时只改这一处；
- 每次失效都记录**当时的现象和改法**，这比重新设计更有用；
- 如果只需要文字、不需要精确到帧，**优先考虑让用户直接把视频/截图给你**——比逆页面稳得多。
